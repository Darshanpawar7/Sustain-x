Safe valve control over MQTT

1

Dashboard signs

HMAC-SHA256 with the valve key over the action, the time and a one-time code

2

Broker delivers

QoS 1 on /cmd; anyone may publish there, so only the signature counts

3

ESP32 checks

Right signature, under 5 minutes old, newer than the last command

4

Valve moves

The servo turns and an answer comes back: 1.24 s measured

The key never leaves the browser. KEY_CHECK on the Serial Monitor prints the same 8-character fingerprint the dashboard shows.

FlowState · Team 10

The public broker lets anyone publish, so a valve command is only accepted if it carries a signature that only the valve key can make. The ESP32 also rejects anything older than 5 minutes or not newer than the last command, so a recorded command cannot be replayed. Demo it live: type the key, compare the fingerprint with KEY_CHECK, press Close and watch the servo turn. A wrong key is refused.
