This answers the protocols criterion. MQTT is publish and subscribe: one connection to the broker stays open, so small messages flow every 2 s with no handshake each time, and commands come back the same way. Telemetry uses QoS 0 because a fresh reading follows; commands use QoS 1. The retained status plus the Last Will tell anyone watching whether the ESP32 is online. HTTPS stores every reading in PostgreSQL and works even where MQTT ports are blocked.
